# AI Prompt Log — Klook ClearTrip v2

## 쟁점 1. 예약 정보 통합 및 위험 확인 Checkbox

**AI 활용 목적:** 기존 Flutter UI 초안을 비판적으로 검토하고, Nielsen 사용성 원칙에 근거하여 설계 변경 여부를 판단하기 위함.

**기록 방식:** 실제 사용자–AI 대화의 주요 요청과 응답을 시간순으로 요약하였다. 원문 그대로 옮긴 부분을 제외한 AI 응답은 핵심 논점 중심으로 정리하였다.

| 요청 (User Prompt) | AI 결과 | 판단 (학생) | 이유 |
|---|---|---|---|
| **1. 최초 주장 및 반론 요청** — 예약 정보의 통합이 인지적 부담을 줄일 수 있다는 주장에 대해 반론을 요청함. | 정보가 한곳에 모인다고 반드시 인지적 부담이 줄어드는 것은 아니며, 정보 과부하와 시각적 복잡성이 증가할 수 있다고 지적함. | **부분 수용** | 정보 과부하의 가능성은 인정하지만, 기존 Klook의 분산된 예약 정보 구조는 정보 탐색 비용을 발생시킬 수 있으므로 통합 방향은 유지하고자 함. |

| **5. 사용자 실제 요청:** “我选择了方案 A。请继续从 Nielsen P05、P07、P08 反驳这个决定，并帮助我检验其合理性。” | P05 관점에서 확인만으로 오류 예방을 보장할 수 없고, P07 관점에서 강제 절차가 효율을 낮출 수 있으며, P08 관점에서 중복 정보가 발생할 수 있다고 비판함. | **핵심 방향 유지, 개선 필요성 인정** | 예약 위험을 확인하는 단계는 필요하다고 판단하였으나, 일률적이고 추상적인 Checkbox는 충분하지 않다는 지적을 수용함. |

| **7. 사용자 실제 최종 결정:** “我决定采用方案 B：保留强制 Checkbox，但根据商品真实条件动态显示具体风险。” | 강제 확인 절차를 유지하면서 환불 불가 여부, 지정 날짜, 무료 취소 가능 기한 등 상품별 실제 정책을 반영하는 방식으로 설계를 정리함. | **최종 채택 — 수정** | 예약 확인 단계의 정확성과 위험 고지 기능은 유지하면서, 불필요하게 추상적인 안내를 줄이고 사용자에게 직접 관련된 정보를 제공할 수 있기 때문임. |

## 최종 의사결정 요약

**유지한 사항**
- Unified Booking Review 화면
- 예약 확정 전 강제 Checkbox
- 날짜, 인원, 가격 및 주요 정책의 명확한 표시

**변경하기로 결정한 사항**
- 일반적인 “예약 내용을 확인했습니다” 문구를 상품별 실제 위험을 반영하는 확인 문구로 구체화
- 상세 정책과 핵심 위험의 정보 위계를 구분

**AI 제안을 그대로 따르지 않은 사항**
- 효율성을 이유로 독립적인 확인 화면이나 강제 Checkbox를 모두 삭제하는 방향

**판단 근거**
- 예약 과정의 효율성은 클릭 수만으로 평가할 수 없음
- 예약 오류 예방과 실제 위험 인지가 중요한 서비스 품질 요소임
- 상품별 구체적인 위험 고지는 일반적인 확인 문구보다 정보의 관련성과 명확성을 높일 가능성이 있음

## 논증 결과 및 한계

이번 AI 대화는 Flutter UI 초안 구현 이후 진행한 설계 검토이다.

최종 결정은 실제 사용자 테스트로 검증된 성과가 아니라, AI 반론과 학생의 재반론을 통해 도출한 설계 개선 방향이다.

실제 코드 변경, 구현 화면 캡처, 사용자 테스트 결과는 별도로 확인해야 한다.
